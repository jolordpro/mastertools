Asked whether artists abuse an unlimited bucket, Bailey says the limited bucket is budget in the cloud and machines locally, so neither is unlimited; with cloud data you can see which artist did not test a render before sending the whole job, and that visibility is what stops abuse [26:42]. He contrasts it with a local farm jammed all night by one job [27:14]. On clients: deadlines and budgets do not change because you use cloud, so cloud means resources meet the production's needs rather than the reverse [49:06].
A small-studio panelist (Moonbot) says with cloud they can answer a radical client change with 'this costs X' instead of 'another month', without disturbing other schedules [50:09]. An audience architect said he sees cloud rendering as an emergency measure and worries about unlimited edits [44:56-47:02]; the panel answered with budget/time limits, not tooling.
